# Olympic Weightlifting Program Generator — CLAUDE.md

Two subsystems around one Postgres database:

- **`oly-ingestion/`** — books / PDFs / web articles → extract → classify → chunk + embed → `knowledge_chunks` and structured tables. Sync psycopg2, CLI only.
- **`oly-agent/`** — the 6-step generation pipeline (ASSESS → PLAN → RETRIEVE → GENERATE → VALIDATE → EXPLAIN), plus `web/`, a FastAPI + HTMX UI with an ARQ background worker. Pipeline is sync psycopg2; `web/` is async asyncpg.
- **`shared/`** — config, DB helpers, LLM client, Prilepin math, constants, exercise mapping. Imported by both.

## Running Things

**Use the root `Makefile`** — it exports `PYTHONUTF8=1` for every recipe.

```bash
make up        # Postgres + PgBouncer + Redis
make migrate   # alembic upgrade head
make web       # uvicorn :8080
make worker    # ARQ worker (separate process — the web UI cannot generate without it)
make test      # all no-key/no-DB tests
make lint      # ruff (pinned version)
```

- Each subsystem has its own `uv` venv. Run `uv run` from that subsystem's directory; never invoke an interpreter by path.
- Running `uv run` directly on Windows: prefix with `PYTHONUTF8=1` or you get cp1252 encoding errors.
- `docker exec` on Windows: drop `-it`, there is no TTY. `docker exec oly-postgres psql …`
- Ports: **5432 = PgBouncer** (all app + ingestion traffic), **5433 = Postgres direct** (psql, Alembic DDL), 6379 = Redis.
- **Model roles** (`shared/config.py`, each overridable by env — `LLM_MODEL`, `LIGHT_MODEL`, `GENERATION_MODEL`, `EXPLANATION_MODEL`; the defaults are **provider-aware** since 2026-09-22: under `openrouter` (the default provider) `llm_model` / `template_model` / `generation_model` / `explanation_model` = `moonshotai/kimi-k3`, `light_model` = `deepseek/deepseek-v4.1-flash`, `judge_model` = `z-ai/glm-5.3-flash`; under `anthropic` the Claude defaults below (`DEFAULT_*_MODEL`) — see `.env.example` and the MODEL-2 revisit in TODO.md): `llm_model` (Sonnet-class) for principle extraction, program-template parsing and vision OCR; `light_model` (Haiku-class) for the classifier fallback, `--contextualize`, `relabel_chunk_types.py` and golden-set grading — always pick it through `shared.llm.light_model_for(settings, explicit)`; `judge_model` (`JUDGE_MODEL`, blank = light model; GLM-5.3 Flash since 2026-09-21 — chosen by `eval/judge_adjudicate.py`, an Opus 5 adjudication of the pairs the candidate judges disputed, not by agreement with the incumbent) grades the golden set — changing it re-freezes the baseline; `generation_model` / `explanation_model` for the agent — **Sonnet 5 with thinking disabled** since the 2026-09-16 baseline (`eval/model_baseline.py`: 8/8 first-try like Sonnet 4.6, −16% cost, −27% latency; adaptive thinking at a 4,096 output budget returned no text). `generation_thinking` / `explanation_thinking` default to `disabled`; set `adaptive` explicitly and raise `generation_max_tokens` / `explanation_max_tokens` to use thinking. `llm_model` (ingestion) moved to Sonnet 5 on 2026-09-20 (MODEL-1b) — every ingestion call site passes `thinking_kwargs(model, "disabled")`; keep that on any new one. Don't hardcode a model id in a call site.
- **Provider** (`LLM_PROVIDER`, `shared/config.py`): `openrouter` (default since 2026-09-22, `OPENROUTER_API_KEY`) — the same Anthropic SDK pointed at OpenRouter's Anthropic-compatible endpoint (`LLM_BASE_URL` to override) — or `anthropic` (`ANTHROPIC_API_KEY`, the only provider with Message Batches). `Settings` rewrites the four model roles to OpenRouter ids (`openrouter_model_id`: `claude-haiku-4-5-20251001` → `anthropic/claude-haiku-4.5`); the family/pricing helpers canonicalise ids back (`canonical_model`), so thinking/sampling/pricing rules hold under either provider. **Build every client through `shared.llm.create_llm_client(settings)`** — never `anthropic.Anthropic(api_key=…)` directly. OpenRouter has no Message Batches: `supports_batches(settings)` is False there and `--batch` degrades to synchronous with a warning. Verified 2026-09-20 through OpenRouter: structured outputs, `thinking: disabled`, image input and `cache_control` all pass through (smoke: cache write 7,204 tokens on call 1, read on call 2).
- **Claude 5 request shape** (`shared/llm.py`): read response text through `message_text(response)`, never `content[0].text` — Sonnet 5 / Opus 5 run adaptive thinking by default, so the first block can be a thinking block, and an empty refusal raises `LLMRefusal`. Pass sampling and thinking options through `sampling_kwargs(model, temperature)` / `thinking_kwargs(model, mode, effort)` — they drop `temperature` on models that 400 on it and no-op `thinking` / `output_config` on models without them. Price with `estimate_cost(in, out, model, cache_read_tokens=…, cache_creation_tokens=…)`; the rate table is `MODEL_PRICING_PER_MTOK`. Thinking tokens count against `max_tokens`: `generate.py` / `explain.py` treat `stop_reason == "max_tokens"` as truncation and double the budget on the next attempt up to `LLM_MAX_TOKENS_CEILING` instead of re-sending the same request.
- **Every JSON reply is schema-constrained (STRUCT-1).** Each LLM call that returns JSON — principle extraction, template parse + continuation, classifier fallback, `relabel_chunk_types.py`, the golden-set grader, and the session generator — sends its schema through `shared.llm.json_schema_kwargs(schema, base_kwargs)` (`output_config.format`, structured outputs). The reply is still a text block, so `message_text` + the existing parsers work unchanged and the fence/regex salvage paths are fallbacks, not the contract. Rules the API enforces with a 400: `additionalProperties: false` on every object, no `minimum`/`maximum`/`minLength`/`pattern`, `minItems` only 0|1, scalar enums, top-level object, and **at most 24 optional properties summed over the whole schema** — which is why principle comparisons travel as `{"op", "values"}` (both required) and `principle_extractor.normalize_comparisons` turns them back into the matcher's `{"lte": 2}`. `output_config` also carries `effort`, so always pass the thinking kwargs as `base` — `{**thinking_kwargs(...), **json_schema_kwargs(...)}` drops one. Enum values come from `shared/schema_enums.py` (mirrored against the migrations by `test_schema_enums.py`, which also walks every ingestion schema for the rules above). Measured cost: ≈ +2.4k input tokens per call. Keep a schema constant across a program's sessions — changing it invalidates the prompt cache.
- API keys live in `oly-ingestion/.env` (gitignored; template in `.env.example`). `OPENAI_API_KEY` → embeddings, `OPENROUTER_API_KEY` → LLM (the default provider; `ANTHROPIC_API_KEY` only with `LLM_PROVIDER=anthropic`), plus `SECRET_KEY`, `POSTGRES_PASSWORD`, `DATABASE_URL`. `shared/config.py` loads the file for both subsystems.
- The Makefile's `AGENT_TESTS` / `INGESTION_TESTS` lists are the source of truth for which suites need no DB or keys. Don't keep test names or counts in prose — they drift.

## Content Routing (ingestion)

Content is **routed before chunking** — the classifier sends each section down exactly one path:

| Content type | Destination |
|---|---|
| Prose / rationale | `chunker` → `vector_loader` → `knowledge_chunks` |
| Tables / programs | `structured_loader` → structured tables |
| If/then rules | `principle_extractor` → `programming_principles` |
| Mixed | Both vector store and principle extraction |

## Invariants

### Module boundaries

- **The agent pipeline must never import from `web/`.** `orchestrator.py` and everything it imports run standalone without FastAPI installed. The single coupling point is `web/worker.py`, which imports `orchestrator` — keep it unidirectional.
- **`COMP_LIFT_REFS` and `EXERCISE_NAME_TO_INTENSITY_REF` live in `shared/exercise_mapping.py`.** Import them; never redefine inline.
- **Numeric constants live in `shared/constants.py`.** Prilepin cap multiplier, session duration, `top_k`, snippet length, rounding increment, similarity threshold, phase-advancement thresholds — import, don't hardcode.

### Database

- **Two drivers coexist.** `shared/db.py` (psycopg2) serves the agent pipeline, `feedback.py`, and ingestion. `web/async_db.py` (asyncpg) is web-only. Never hand an asyncpg connection to psycopg2 code or vice versa. The one deliberate crossover is `complete_program()` in `queries/program.py`, which opens a dedicated psycopg2 connection because `feedback.py` uses psycopg2 internals.
- **asyncpg placeholders are `$1`, `$2`, …** — not `%s`. Dynamic `IN` clauses use `= ANY($1::int[])` with a Python list as one argument.
- **asyncpg has no `conn.commit()`.** Use `async with conn.transaction():` or the `get_db()` dependency, which wraps it. Commit on clean exit and rollback on exception are automatic.
- **asyncpg needs JSONB codecs registered** (`init=_init_connection` in `async_db.py`), otherwise JSONB columns arrive as raw strings and templates raise `AttributeError: 'str' has no attribute 'adherence_pct'`.
- **`chunk_type` is a Postgres enum** — filter with `chunk_type::text = ANY(...)`, not `chunk_type = ANY(...)`.
- **Embeddings go through `loaders/embedders.py`.** `make_embedder(settings)` returns one `Embedder` (`embed_documents` / `embed_query`) for `EMBEDDING_PROVIDER` ∈ {`openai`, `openai_compat` (any `/v1/embeddings` server via `EMBEDDING_BASE_URL`), `local` (sentence-transformers, `loaders/local_embedder.py`)}; `VectorLoader` holds it and never calls an embedding API itself — `_embed_batch` / `_embed` delegate, and the query LRU is keyed on `(provider, model, dim, text)`. Every provider fits vectors to `embedding_dim` with `fit_dimension` (normalise, zero-pad or truncate) so a model of another native width needs no schema change. A new provider is a subclass plus a `make_embedder` branch; model-specific query instructions stay inside the provider.
- **Every `knowledge_chunks` row records its `embedding_model`.** `VectorLoader` writes `settings.embedding_model` on insert and `similarity_search` filters `embedding_model = settings.embedding_model`, so vectors from two models never share a ranking. The corpus is on `text-embedding-3-large` at `embedding_dim = 1536` since 2026-09-22 (EMBED-1, the code default; the loader passes `dimensions=` for `text-embedding-3-*`). To change models, flip the setting, run `oly-ingestion/reembed.py`, then `build_golden --extend` so both models are scored on the same labels (docs/RETRIEVAL_EVAL.md); until the re-embed finishes, searches under the new setting see only the re-embedded rows (RAG-M8).
- **Filtered vector search needs `hnsw.iterative_scan`.** pgvector's HNSW scan collects `ef_search` candidates and only then applies the WHERE clause, so a selective `chunk_type` / `min_similarity` filter can return fewer than `top_k` rows or none. `VectorLoader.similarity_search` sets `hnsw.iterative_scan` + `hnsw.ef_search` (from `shared/constants.py`) transaction-locally on every call, guarded by a savepoint for pre-0.8 pgvector. Any new query that orders by `embedding <=>` under a WHERE must go through it or repeat the `set_config` calls.
- **PgBouncer:** `statement_cache_size=0` is required in `init_async_pool()` (asyncpg's prepared-statement cache doesn't survive transaction pooling). `AUTH_TYPE` must be `scram-sha-256` — `md5`/`trust` make PgBouncer hash the password internally, leaving it unable to complete the SCRAM handshake Postgres 16 requires. The healthcheck must pass `-d ${POSTGRES_DB}`; bare `pg_isready` targets a database named after the user, which PgBouncer won't route.
- **Program deletion:** `training_logs.session_id` and `training_log_exercises.session_exercise_id` have no `ON DELETE CASCADE` and must be NULLed explicitly first. See `delete_program()` in `queries/program.py`.
- **`date_of_birth` replaced `age` on `athletes`.** The `age` column still exists but is never written. Compute age from `date_of_birth`; don't reintroduce `age` into INSERT/UPDATE.
- **`lift_emphasis`, `strength_limiters`, `competition_experience`** must be included in every profile SELECT/UPDATE and setup INSERT — `generate.py:build_session_prompt()` injects all three into the LLM prompt. So must **`biological_sex`, `date_of_birth`, `bodyweight_kg`, `weight_class`** (and `timezone`, which dates the age) since AUD-5: `assess.athlete_demographics` maps them onto `AthleteContext` (`age_years` / `age_band` from `date_of_birth` via `demographics.age_from_dob` + `AGE_BANDS`), the prompt's Athlete Profile shows a `Demographics:` line (omitted when all are blank), and `retrieve.build_session_query` appends `SEX_QUERY_QUALIFIERS` / `AGE_BAND_QUERY_QUALIFIERS` (female, youth, masters only — every other athlete's query stays byte-identical to the golden set). `assess` reads `SELECT *`; keep any narrowed athlete SELECT feeding the pipeline carrying them.

### Agent pipeline

- **The agent venv needs `openai` + `tiktoken`.** `orchestrator._make_vector_loader` imports `VectorLoader` from `oly-ingestion/` at runtime and degrades to *no knowledge context* with only a warning when the import or construction fails — a worker on a venv without them generates uncited programs (DOG-1 finding). Both are core deps in `oly-agent/pyproject.toml`; orchestrator unit tests patch `_make_vector_loader` to `None` so they never reach OpenAI or Postgres.
- **Production retrieval is dense-only since AUD-3; hybrid is kept, off.** Under `text-embedding-3-large` dense-only beat every RRF weighting on the gate (nDCG@5 0.796 vs 0.712 equal-weight, 0.782 at lexical weight 0.1 — docs/RETRIEVAL_EVAL.md), so `HYBRID_SEARCH_ENABLED = False`; `retrieve.py` passes it to every search. `similarity_search(hybrid=True)` still fuses the vector leg with a lexical leg over the generated `tsv` column (migration 0009, GIN-indexed): score = `1/(RRF_K + vec_rank) + HYBRID_LEXICAL_WEIGHT/(RRF_K + lex_rank)` over `HYBRID_CANDIDATES_PER_LEG` per leg, each overridable per call (`lexical_weight`, `rrf_k`, `candidates_per_leg`; weight 0 = dense path); `min_similarity` applies to the vector leg only, metadata filters to both, the chunk_type preference re-scaled to `CHUNK_TYPE_PREFERENCE_BOOST_RRF`; queries become an OR-of-terms `to_tsquery` (`_lexical_tsquery`). `build_golden` pools hybrid at weight 1.0 so lexical-only candidates keep being graded. Rows carry `similarity`, `lex_score`, `rrf`, `score` (RAG-M1).
- **The listwise rerank exists and is off (`RERANK_ENABLED`).** `oly-agent/rerank.ListwiseReranker` reorders the top `RERANK_TOP_N` (15 — the depth the golden set grades) in one schema-constrained light-model call per query, cached per (model, query, ids); any error or malformed reply keeps the retrieval order, and `retrieve.default_reranker` turns a build failure into "no rerank". Measured: +0.02 aggregate nDCG but a session-family loss within its own run-to-run noise, so it stays off; `retrieve._rank` sorts by `rerank_score` when a rerank ran. Measure any reranker with `run_eval --rerank` at a depth the golden set has graded — ungraded chunks score 0.
- **`chunk_type` is a soft retrieval preference, never a hard filter.** It is a first-match keyword label (`pipeline._infer_chunk_type`) and `concept` is ~61% of the corpus; the old `chunk_types=[...]` filter left session generation 15% of the chunks and none of the deload content (RAG-H2). `retrieve.py` passes `preferred_chunk_types`, which `similarity_search` applies as `CHUNK_TYPE_PREFERENCE_BOOST` on a similarity-ranked candidate pool. Don't reintroduce `chunk_types=` in a production query. The eval must use the same preference to be production-parity.
- **Prilepin zones cover 55–100%**, including the 65–70% transition band. `get_prilepin_zone()` returns `None` only below 55%; the fallback in `compute_session_rep_target` handles that deload case alone.
- **`plan._advance_phase()`** walks `general_prep → accumulation → intensification → realization`, and realization cycles back to accumulation. Gated on adherence ≥ 70% and make rate ≥ 75%; RPE deviation > 1.5 blocks advancement. `_apply_outcome_adjustments()` nudges volume/intensity on non-deload weeks from the previous `outcome_summary`.
- **`feedback._compute_phase_verdict()` mirrors `plan._advance_phase` + `_apply_outcome_adjustments` exactly.** Both read their thresholds from `shared/constants.py` — change one and you must change the other.
- **`outcome_summary` (JSONB) fields**, all written by `feedback.save_outcome()` and read by `plan.py`, `generate.py`, and templates: `adherence_pct`, `avg_rpe_deviation`, `avg_make_rate`, `make_rate_by_lift`, `avg_weekly_reps`, `rpe_trend`, `make_rate_trend`, `maxes_delta`, `athlete_feedback`, `phase_verdict`. psycopg2 returns it as a dict already — pass it as a parsed dict, don't re-parse.
- **Weeks 2..N generate concurrently, anchored on week 1 (AUD-4).** `orchestrator.run` generates week 1 alone, then weeks 2..N `GENERATION_WEEK_CONCURRENCY` at a time (`ThreadPoolExecutor`; days in order within a week; `week_concurrency=1` is fully sequential). Weeks are independent — `week_cumulative_reps` / `week_already_prescribed` reset per week — and the program-level state is `_SpendGuard` (spend + stop flag under a lock; admits a session while `spent + in_flight × avg ≤ limit`, which is the sequential rule at concurrency 1). Each worker opens its **own** psycopg2 connection for its `generation_log` rows; retrieval (`VectorLoader` connection + query cache) stays on the main thread, prefetched in (week, day) order, and the main thread inserts worker sessions in (week, day) order. Deadline / cost aborts are recorded per week and the draft is marked once. Continuity comes from week 1, not week N−1: each later session gets week 1's same-day session (`summarize_block_template`, ≤ `BLOCK_TEMPLATE_MAX_CHARS`) as `block_template`, rendered below the marker as `## Block Template (Week 1, Day N)` at every concurrency so prompts don't depend on the setting. Any new per-session step inside `_generate_week` must be thread-safe or run on the main thread.
- **Every generation attempt logs its retrieval set, and citations drive `source_chunk_ids`.** The orchestrator builds `retrieval_set` (`[{label: "C1", id, chunk_type, source_id, similarity, score, session_query}, …]`) from the session's context chunks and `generate_session_with_retries(retrieval_set=…)` writes it to `generation_log.retrieval_set` (JSONB, migration 0010) on every attempt. `weight_resolver.attach_source_chunk_ids` maps `[Cn]` citations in `selection_rationale` onto `retrieval_context["context_chunks"]` (prompt order); only when an exercise cites nothing does the old session-level heuristic apply. Keep the label order identical between the prompt block, `retrieval_set` and `context_chunks` (RAG-M5).
- **`generation_log` rows carry each attempt's cache-aware cost and validation warnings (AUD-6).** `_log_generation` prices with the attempt's own `cache_read_tokens` / `cache_creation_tokens` (from `usage_tokens`), and `parsed_response` is `{"exercises": [...], "_validation_warnings": [...]}` (null when Step 5 didn't run) — there is no warnings column, and `validation_errors` stays errors-only because `eval/model_baseline` counts it.
- **Knowledge context is retrieved per session, not per program.** `retrieve()` keeps the program-level paths (fault exercises, templates, fault + limiter chunks); the session prompt's chunks come from `retrieve.retrieve_session_context()`, called by the orchestrator for every session with a per-program `cache` keyed by the query string (`build_session_query`: template movements + phase + intensity band + level + faults/emphasis/limiters). `compose_session_context` picks ≤ `MAX_CONTEXT_CHUNKS`: fault chunks round-robined across faults first (when the athlete has faults), then the session's chunks by score, ≤ `MAX_CHUNKS_PER_SOURCE_IN_CONTEXT` per source *within each group* (fault picks and session picks budget separately — a shared cap let two Everett fault chunks leave every snatch-variations session with no session context, DOG-1). The prompt labels them `[C1]…[Cn]` and asks for citations by label. Pass `context_chunks=` to `build_session_prompt`; the fallback composition exists only for callers without a vector loader (RAG-H4). **Composition is stateful per program (AUD-3):** a `ContextDiversityState` rides in that per-program cache (`CONTEXT_STATE_KEY`; or pass `state=`) — fault chunks are taken least-shown-first so they rotate across sessions, and a source holding `MAX_SOURCE_SHARE_IN_PROGRAM` of the program's slots is passed over in a first pass, with a second pass filling any empty slot (a soft cap: it never starves a session the way the shared cap did). compose holds the state's lock per session; the orchestrator composes on the main thread in (week, day) order, so the rotation is deterministic — keep it there. Measure with `eval.context_simulate <program>` (replays logged session queries; program 29: 9 → 16 distinct chunks, max source share 0.50 → 0.39, no chunk in ≥ 50 % of sessions).
- **Competition-lift volume comes from a selectable table (PLAN-3d).** `shared/volume_tables.session_rep_target(table, …)` is the one entry point for plan (weekly budgets) and orchestrator (session targets); `prefs.volume_table` ∈ `prilepin` (default, `shared/prilepin.py`) / `medvedev` (monthly NL by level and period × 0.5 comp-lift share, every number from the corpus — see the module docstring). `WeekTarget.volume_table` carries the choice to the prompt (`_volume_table_section`) and validator (Prilepin's per-session zone caps only apply under `prilepin`; per-set limits always). Add a table only with sourced numbers.
- **Squats and pulls follow a strength curve (PLAN-3c).** `phase_profiles.STRENGTH_CURVE` gives a squat band (% of the squat max) and a pull band (% of the competition lift) per phase and for deload weeks, each row citing the principle ids it came from; `plan` puts it on `WeekTarget.strength_targets`, the Program Plan prompt shows it, and `validate` check 13 only *warns* (±`STRENGTH_CURVE_TOLERANCE_PCT`) — never an error, so it never costs a paid retry. Change a band only with a source.
- **Complexes are first-class (PLAN-3a).** `exercise_complexes` (migration 0019: deduped, `UNIQUE(name)`, `movement_family`, `complexity_level`) is offered through `retrieve.select_available_complexes` (every component in this athlete's catalogue, none on the avoid list) and the static prompt section `## Available Complexes`. The model prescribes one like an exercise; `complexes.annotate_complexes` (after name validation, before `validate_session`) sets `reps` = the complex total, `complex_id`, `notes = "complex 1+2"`. **Judge a complex by its components, never by `is_competition_lift(name)`** — "Snatch + Overhead Squat" contains `squat`: `counts_as_competition_lift`, `reps_for_prilepin` (largest comp component) and `comp_reps_per_set` drive the ceiling, per-set and volume checks. Display with the `prescription` filter (`4×(1+2)`).
- **Principles are loaded wide and chosen per session (AUD-1).** `plan._load_principles` returns ≤ `MAX_PRINCIPLE_CANDIDATES` rows in `PROMPT_PRINCIPLE_CATEGORIES` only (technique/recovery rules — bar-drop etiquette, doping bans — are priority 10 with empty recommendations and used to fill every slot), with an actionable recommendation, `duplicate_of IS NULL`, the source title joined, `ORDER BY priority DESC, id`. The orchestrator calls `select_principles(…, limit=MAX_PRINCIPLES_IN_PROMPT, query=build_session_query(…))`: conditions first, then priority + `PRINCIPLE_RELEVANCE_WEIGHT` × lexical overlap with the session query (no embeddings), ties by id, ≤ `MAX_PRINCIPLES_PER_CATEGORY` per category — the validator gets the same list the prompt shows. Each prompt line is `format_principle_line`: `[id] name — <recommendation json> — <rationale ≤ PRINCIPLE_RATIONALE_PROMPT_CHARS> (<source>)`, below the static/dynamic marker. Injury / rehab rules (name or rationale matching `INJURY_PRINCIPLE_TERMS`) are skipped when the athlete has no injuries (`state['has_injuries']`) — the condition vocabulary has no injury key, so they otherwise read as unconditional.
- **The session prompt is static-first and the prefix is cached.** Everything before `PROMPT_STATIC_DYNAMIC_MARKER` (`## Program Plan`) is identical for all sessions of a program — rules, athlete, maxes, history, exercise catalogue, avoid list, substitutions; everything after is per week/session (plan, template, Prilepin, already-prescribed, principles, context, templates, instructions). `generate.prompt_content_blocks` sends the prefix as a `cache_control: ephemeral` text block when it is ≥ `PROMPT_CACHE_MIN_CHARS`, and validation retries only append to the dynamic tail. Add new program-level sections *above* the marker and week/session-level ones *below* it; never put week-dependent text (ceiling, deload) in the rules block (RAG-L3). Each section is its own `_*_section` helper joined by blank lines, and `tests/fixtures/prompt_golden_*.txt` pin the output byte for byte — regenerate them with `test_generate_utils._write_golden_prompts()` only when a prompt change is intended (AUD-6).
- **Prompt length budget:** measured 2026-09-16 on the real athlete: 17–20.7k chars against `PROMPT_LENGTH_WARN_CHARS = 20,000` before DOG-1h, ~13–16k after. The dominant sections are `MAX_CONTEXT_CHUNKS` × `SNIPPET_MAX_CHARS` (4 × 1,500) knowledge chunks — a longer chunk (most of them; median ≈ 3.8k) is shown as `shared/excerpt.focused_excerpt(text, query, SNIPPET_MAX_CHARS)`, the sentences matching the chunk's `retrieval_query` (fault / limiter chunks) else its `session_query`, never a head cut (AUD-2; keep new chunk renderers on it) — Available Exercises (`_exercise_line`, ~60 chars each: `name [family, cN] sets x reps @ % | for: <athlete's faults only>`) and, by day 4, Already Prescribed This Week (~1.1k). If the exercise catalogue passes ~150 entries, add `MAX_EXERCISES_IN_PROMPT` to `shared/constants.py` and slice `retrieval_context.available_exercises` in `build_session_prompt`. Input tokens per call stay at 2–3k because the static prefix is cached; the budget is about the model's attention, not cost.

### Ingestion pipeline

- **`--batch` routes the expensive ingestion calls through the Message Batches API (COST-1).** `shared.llm.run_message_batch(client, {custom_id: create-kwargs})` submits, polls and returns `{custom_id: Message | BatchRequestFailed}`, re-sending `max_tokens`-truncated replies with a doubled budget (the batch twin of `create_message_growing`). `PrincipleExtractor.extract_batch` and `PDFExtractor(batch=True)` build their requests from the same `_request_params` / `_ocr_request` the synchronous path uses — keep both paths sharing one request builder and one response parser so they can't drift. In `pipeline.ingest`, principle sections are queued during the section loop and flushed by `_flush_principle_batch` after it; because the loop has already checkpointed past them, a failed batch **rewinds the checkpoint to `resume_from`** before re-raising. `--contextualize`, template parsing and the classifier fallback stay synchronous (per-chunk before embedding; sequential continuation windows; rare).
- **Add every new source title to `SOURCE_PROFILE_MAP` (`processors/chunker.py`) before ingesting it.** Matching is substring-on-title; an unrecognised title silently falls back to the 900-token `programming` profile. Profiles are listed in `docs/CORPUS.md`. This applies to books and papers only — the web path (`ingest_web.py`: Catalyst, Charniga and `--site urls` lists) sizes chunks dynamically via `for_web_article(word_count)` and never consults the map. Papers use the `research` profile (700/150).
- **Curated URL lists are the third web path.** `ingest_web.py --site urls --url-file sources/url_lists/<name>.json` (the only committed thing under `sources/`, plus one script — `cissik_medvedyev.py`, which swaps a post's table images for transcriptions and hands the page to `fetch_generic_article(url, author, html=…)`) runs `fetch_generic_article`: container-first extraction (pick the tightest of `.entry-content` / `article` / `main` / body that still holds the article, *then* drop share/related/affiliate/TOC/hidden widgets — never an element containing the longest `<p>`, since theme wrappers like `content-sidebar-wrap` match the junk regex too), author from `<meta name="author">` or the `by <Name>` byline, `_strip_generic_chrome` for skip links / bylines / the trailing related-posts block, and `GENERIC_MIN_WORDS` (400) to drop video landing pages. Catalyst URLs in a list still go through `fetch_article`. Progress is shared across lists in `sources/urls_progress.json`.
- **Open-access papers come from Europe PMC as JATS, not PDFs.** `extractors/jats_extractor.py` (`python -m extractors.jats_extractor <PMCID> <dest.txt>`) renders `fullTextXML` as `#` headings + `

` paragraphs + tab-separated table rows and drops references; ingest the `.txt` with `pipeline.py --type article`. Publisher and repository PDFs mostly 403 scripted fetches (MDPI, Springer, PMC, ECU, Salford, ScienceDirect) — when a paper has no PMCID, the PDF has to be saved from a browser.
- **Topic tags match whole words; `athlete_level_relevance` is retired.** `keyword_tag` uses `\b`-bounded matchers built from `KEYWORD_TO_TOPIC` (substring matching tagged *requiring* as RIR and *speaking* as peaking); after editing the keyword map run `retag_chunks.py`. `similarity_search` no longer takes `athlete_level` and the loader no longer writes `athlete_level_relevance` — the column was NULL on every row and its index is dropped (migration 0011). `topics`, `information_density` and `contains_specific_numbers` are still written for the eval's topic-hit metric and future soft boosts; they are not production filters (RAG-M7).
- **`--contextualize` writes an LLM retrieval-context prefix per chunk (opt-in).** `processors/contextualizer.py` sends the enclosing section as a cached system block and asks for 1–2 sentences per chunk; `apply_context` inserts them between the preamble and the body of `content` (what gets embedded) and stores them in `knowledge_chunks.context_prefix` (also part of the generated `tsv`). `raw_content`, the dedup hash and what the prompt shows are unchanged. Run it on the re-ingest so chunks are embedded once; a Haiku-class `--context-model` is enough (RAG-M3).
- **Token counts are real tokens.** `processors/tokens.py` counts with tiktoken `cl100k_base` (the `text-embedding-3-*` tokenizer) and falls back to words × `TOKENS_PER_WORD_FALLBACK` only when the encoder can't load; the chunker's `_estimate_tokens` and the embedding cap (`EMBED_MAX_TOKENS`, by tokens, not the old 30k chars) both go through it. Numeric notation tokenises at ~5× the word count, so profile sizes now mean what they say. `_chunk_section` splits a paragraph longer than the profile on sentence boundaries (`_split_long_paragraph`) instead of emitting one oversized chunk (RAG-M2).
- **Never call `get_text(separator='\n')` on content headed for the chunker.** Both `epub_extractor.py` and `html_extractor.block_text()` insert `NavigableString('\n\n')` after block tags (`p`, `h1`–`h6`, `li`) before `get_text(separator='')`. `_chunk_section` splits on `\n\n`, so single newlines collapse an entire chapter into one oversized chunk (a 146k-char chapter → 1 chunk instead of ~47).
- **EPUB chapters are classified individually; PDF pages are not.** Each EPUB document item is already a logical section — classify them one by one. PDF pages are rendering units: `pipeline._prepare_pdf_pages()` strips running heads/folios (`extractors/page_text.strip_running_heads`) and joins pages (`join_pages`, re-attaching sentences and hyphenated words split by the break) into one document *before* classification. Classifying PDFs page by page made chunk = page for every PyMuPDF source (RAG-H1). `pdf_extractor` must keep using `get_text("blocks")` — plain-text mode has no blank lines between paragraphs.
- **OCR session labels are not headings, and training logs chunk per week.** Vision OCR renders Medvedev's session labels as `# 4 - February (Monday)` / `# 8 February (Wednesday)` / `# 4. - January (Friday)` / `# 2 - 1. P. Cl.`; `processors/sectioning.MARKDOWN_HEADING_RE_SRC` (a `#{1,3}\s+` heading with `OCR_LABEL_LOOKAHEAD`: not a number followed by a month, a digit or a parenthesis) is the **one** markdown-heading pattern, used by both `classifier._split_into_sections` and the chunker's `SECTION_BREAK_PATTERNS` — there are two splitters, and fixing only the classifier left chunk = session (MEDVEDEV: 613 chunks of ~320 chars; fixed → 143 of ~1,430). `Week N` is not a section break either — the week flush below handles it and keeps the label in the chunk text. `SemanticChunker._chunk_section` starts a paragraph at any `Week #? N` line and closes the chunk there once it holds ≥ `WEEK_BOUNDARY_FLUSH_FRACTION` (0.7) of the profile's size, with no tail overlap across the week boundary — a log week is 350–650 tokens (1–2 per chunk), an exercise-listing week ~150 (3–4 per chunk; at 0.4 those came out as ~300-char chunks). Applies to every profile; only week-labelled text triggers it. Both OCR paths regrow a `max_tokens`-truncated page group up to `LLM_MAX_TOKENS_CEILING`; batch `custom_id`s must match `[A-Za-z0-9_-]{1,64}` (`run_message_batch` rejects others before submitting).
- **Sections are capped and fragments merged before classification.** `processors/sectioning.py` splits any heading-delimited section over `CLASSIFY_SECTION_MAX_CHARS` at paragraph boundaries (so one program table can't route a whole joined chapter to the template parser) and folds sections under `MIN_SECTION_CHARS` whose heading is weak (`\d+.\d+ …`, `Week N …`) back into their neighbour with the heading line restored — those regexes over-fire on table rows. Strong headings (`Chapter`, `PART`, markdown `#`) are never merged. The chunker's `_split_on_sections` applies the same merge.
- **Principle numbers must come from the text (PRIN-AUDIT).** The session prompt shows a principle as `name: recommendation`, so an invented `intensity_ceiling` reaches generation as an instruction. The fix is post-hoc, not in the prompt — a stricter `EXTRACTION_PROMPT` (numbers only from the text) was tried on 2026-09-22 and made Kimi drop ~60 % of the *supported* numbers and return nothing for two whole windows (TODO PRIN-AUDIT). Every ingest ends with `principle_audit.run_audit_pass` (`--no-principle-audit` to skip), which checks each numeric claim against the document just classified + the source's chunks and strips unsupported *recommendation* keys (backup appended to `logs/prin_audit_ingest_backup.jsonl`; conditions are reported, never changed — dropping one would make a rule unconditional). Whole-corpus runs: `principle_audit.py --report / --apply --backup … --fetch-web …`. Empty replies from the extractor are re-asked (`PRINCIPLE_EMPTY_RETRIES`).
- **Duplicate principles are marked, not deleted.** `programming_principles.duplicate_of` (migration 0016) points a restated rule at its canonical twin (lowest id), set by `dedupe_principles.py` (embedding prefilter → Jev `Noul`); `plan._load_principles` filters `duplicate_of IS NULL`. Any new query that feeds principles to a prompt must do the same. Re-run after a re-ingest.
- **Quarantined chunks never rank.** `knowledge_chunks.quarantined` (migration 0015) marks non-content — book indexes, reference/URL lists, TOCs, title pages — found by `quarantine_chunks.py` (a Jev `Noul` per chunk, `JUNK_QUARANTINE_THRESHOLD`, score kept in `junk_probability`); `similarity_search` adds `NOT quarantined` to both legs. Rows stay for hashes, dedup and provenance. Any new query that ranks chunks must carry the same predicate. Re-run after a re-ingest (new rows default to not quarantined).
- **Dedup is global by content hash** (SHA-256 of `raw_content`). The same text in two sources is embedded once, so the second source's run reports `chunks_created=0` for those sections. Dedup happens before the embedding call. Provenance is kept in `chunk_sources` (migration 0012): the loader writes a `(chunk_id, source_id)` row for every new chunk **and** for every duplicate it skips, so `knowledge_chunks.source_id` means "first seen in" and `chunk_sources` answers "which sources contain this" (RAG-L5).
- **`vector_loader` guards the embedding call:** empty chunks are skipped (OpenAI 400s on empty strings) and texts over 30k chars are truncated (8192-token limit) with a warning; the chunk is still stored.
- **Both entry points route sections through `processors/section_processor.SectionProcessor` (I-L11).** `pipeline.py` and `ingest_web.py` share one `process()` — prose → chunk → `validate_chunk` → (contextualize) → embed; MIXED → prose + principles; PRINCIPLE → principles (queued in `--batch`); PROGRAM_TEMPLATE / TABLE / EXERCISE → the caller's `structured` handler (`pipeline._process_structured`), or prose when there is none (web) or it declines (a TABLE with no rows). Fix routing there, not in an entry point. `CHUNK_TYPE_KEYWORDS` / `infer_chunk_type` live there too (re-exported from `pipeline`). A section-level error must call `SectionProcessor.rollback()` (`pipeline._rollback_connections()` delegates) — without it every later section fails with "transaction is aborted". Web ingests now also get the per-article Jev quarantine pass (`--no-quarantine` to skip).
- **`_llm_classify()` fires only below 0.6 confidence.** Short sections (<50 words) score 0.60 and stay heuristic; plain narrative scores 0.80. Only genuinely ambiguous mid-length sections — a weak signal that cleared no category — score 0.55 and reach the LLM.
- **PDF extraction falls back** PyMuPDF → pdfplumber (under 100 chars extracted) → vision OCR (still under 100 chars **and** `--vision` passed; opt-in because it costs money). OCR text is cached per page in `sources/.ocr_cache/<sha256 of the PDF>.json`, keyed by the OCR model (`extractors/ocr_cache.py`); only page groups with a missing page reach the model, so re-ingesting an unchanged scan is free. `--no-ocr-cache` bypasses it; `--force-vision` skips a text layer that is one block per line. **Every OCR'd page passes the OCR-QA gate** (`processors/ocr_quality.py`): no-reference signals (blank with ink, short vs neighbours, echo of the previous page, garbled / non-ASCII share — `OCR_*` in `shared/constants.py`) flag suspects, each suspect is re-OCR'd alone as an independent geometric view (`OCR_SECOND_VIEW_DPI` + `OCR_VIEW_ROTATIONS_DEG`), a disagreement gets a third view and `resolve_views` keeps the best-agreeing pair; page text is assigned by the `=== Page N ===` number so a repeated or dropped header can't shift the group. Unresolved pages are logged at ERROR and land in `ingestion_runs.result` (JSONB, migration 0017: the whole stats dict, `ocr_pages_unresolved` / `ocr_verdicts`) and in `sources/.ocr_cache/<sha>.report.json`. `--ocr-postcorrect` adds guarded LLM post-correction for still-garbled pages (off by default). Every `pipeline.py` ingest (and every `ingest_web.py` article) ends with a Jev quarantine pass over the new source (`quarantine_chunks.quarantine_source` via `section_processor.run_quarantine_pass`, `--no-quarantine` to skip). Never ask the model to grade its own transcription — multi-view agreement is the signal that works. `ocr_audit.py` re-runs the checks on existing caches; `--clear-suspects` drops them so the next ingest re-OCRs those pages.
- **OCR and contextualisation run concurrently.** `_extract_with_vision` keeps `OCR_CONCURRENCY` page groups in flight (ThreadPoolExecutor; pages are rendered on the main thread because PyMuPDF documents are not thread-safe, so `_ocr_batch` takes pre-rendered `images=`), caches and heartbeats each group as it completes, and the cache is saved per group so a killed run keeps its pages. `contextualize` sends the first chunk alone (warms the cached section block) and the rest `CONTEXTUALIZE_CONCURRENCY` at a time. The client is built with `max_retries=0` + `LLM_REQUEST_TIMEOUT_S`; `create_message_with_retries` owns retries (OCR: `OCR_REQUEST_ATTEMPTS` × `OCR_REQUEST_TIMEOUT_S`) so a hung socket surfaces in minutes, not the SDK's silent 10-minute × retries.
- **Program templates parse incrementally.** `_parse_program_template()` splits sections over 5,000 chars into 5,000/500 overlapping chunks: the first uses `_PROGRAM_PARSE_PROMPT`, the rest `_PROGRAM_CONTINUATION_PROMPT` (weeks with `week_number > last_seen`), deduped through a `seen_weeks` set. `max_tokens=4096` on all program parse calls.
- **`structured_loader.load_program()` validates before INSERT** — `duration_weeks >= 1`, `sessions_per_week` in `[1, 14]` — and infers both from the parsed weeks when the LLM returns 0. It warns and returns `None` rather than tripping a DB check constraint.

### Web UI

- **CSS is compiled and committed, not loaded from a CDN.** `web/static/tailwind.css` is built from `web/tailwind/` by `make css`; every JS/font asset is vendored under `web/static/`. Adding a utility class a template didn't already use means rebuilding, or it won't exist in the output.
- **The palette lives in `web/tailwind/tailwind.config.js`, by role.** Use `paper`/`line`/`ink`/`navy` (and `canvas`), never Tailwind's default `gray` — it is intentionally left cool and unremapped, so a stray `text-gray-500` renders visibly off-theme. `ink` shades are for cream surfaces and `navy-100`/`navy-200` for text on the navy nav; conflating them is what took the nav to 2.58:1. `web/tailwind/build_palette.py` regenerates the accent tints and audits contrast.
- **Do not add `passlib`.** passlib 1.7.4 is incompatible with bcrypt 5.x — `web/auth.py` wraps the `bcrypt` library directly (`bcrypt.hashpw` / `bcrypt.checkpw`).
- **Middleware order:** `add_middleware` wraps in reverse, so `SessionMiddleware` must be added *after* `AuthMiddleware` to run outermost. The session has to be populated before the auth guard reads it.
- **HTMX auth expiry:** `AuthMiddleware` checks the `HX-Request` header and returns an `HX-Redirect` response header with status 200 instead of a 302, so HTMX does a full-page redirect rather than swapping the login page into a fragment.
- **Jinja `{% set %}` is loop-scoped.** To accumulate across iterations use `{% set ns = namespace(key=[]) %}` and `ns.key = ns.key + [item]` — see `exercise_log_section.html`.
- **Custom Jinja filters are registered in `web/app.py`:** `urlencode` (`quote_plus`, not a Jinja builtin) and `parse_rationale` (splits the rationale on `#` headings into `{heading, body}` dicts, which is also what makes per-section page breaks work in PDF export).
- **`exercise_log_entry.html` needs `session_id` from both call sites** — included from `exercise_log_section.html` (set before the loop) and rendered directly by `update_exercise_log` (passed explicitly). Keep both paths in sync.
- **`upsert_athlete_max()` returns `(is_pr, prev_kg)`** — always destructure; the program router feeds `is_pr` to the maxes partial for the PR banner.
- **PDF export is browser print.** `exportPDF()` opens every `<details>` before `window.print()`; `@media print` CSS handles chrome (`print:hidden`), restores responsive-hidden columns (`print:table-cell`), and sets `page-break-inside: avoid`.
- **Responsive conventions:** forms use `grid grid-cols-1 sm:grid-cols-2`; tables hide columns progressively with `hidden sm:table-cell` / `md:` / `lg:`; the exercise log entry toggles a mobile and desktop variant with `hidden sm:flex` / `sm:hidden`.

### Tests

- **The no-key suites are independent of the developer's `.env`.** `shared/config.py` loads `oly-ingestion/.env` once at import; both `tests/conftest.py` files then pin `LLM_PROVIDER=anthropic` and drop the model-role / thinking overrides, so `Settings()` in a test resolves to the code defaults (Claude ids) whatever the dev `.env` says. A test that needs a provider sets it explicitly (`Settings(llm_provider=…)` or `os.environ`). Don't pin individual tests instead.
- **Router tests authenticate with signed session cookies, not middleware patching.** `BaseHTTPMiddleware` captures `self.dispatch_func = self.dispatch` at construction, so `patch.object(AuthMiddleware, "dispatch", …)` has no effect after the app is built. Build the cookie with `itsdangerous.TimestampSigner(secret).sign(base64(json(session)))` and set it on the TestClient jar; `get_settings().secret_key` gives the live key post-init.
- **The `get_db` override must be `async def _db_override(): yield mock_conn`.** A sync generator won't satisfy async dependency injection.
- **The asyncpg pool is created in the FastAPI `lifespan` handler** inside a try/except so `TestClient` works with no Postgres running. Tests override `get_db`, so `get_async_pool()` is never called.
- **`INTEGRATION_TESTS=1` gates tests needing real APIs or a live DB** inside otherwise-mocked files, via `_integration_only()` raising `_Skip`. Used in `test_pdf_extractor.py`, `test_retag_chunks.py`, `test_orchestrator.py`, and `test_web_routers.py`; `test_classifier.py`'s four live-LLM tests use a `pytest.mark.skipif` on the same variable.
